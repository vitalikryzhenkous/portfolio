## The problem: practise, don't read

Reading solutions feels productive and teaches little. I wanted to write code, run it against tests immediately,
see the pattern behind it, and move through a plan — and do the same for behavioral answers and system design.

## Python in the browser, safely

- **Pyodide** runs in a **Web Worker**, so a runaway loop never freezes the page. Each run has a **6-second
  timeout**; on timeout the worker is terminated and rebuilt.
- A small test harness is injected into the worker; your code runs against the same tests the content was
  validated with.
- Nothing is executed on the server.

## Content is treated like code

- In the **Docker build**, a validator checks the schema of behavioral and system-design files, and another one
  runs every reference solution, filled-in blank and primer drill against its tests in CPython — at least 4 tests
  per exercise. **A failing exercise stops the image from being built.**
- The build also asserts that every case the plan links to exists.
- Material from public sources is credited and rewritten in my own words.

## Small backend, careful with data

- **FastAPI + SQLite** stores progress: a 5 MB cap per state, at most one snapshot per hour, the last 60 kept,
  export and restore.
- A three-stage Docker build: pinned front-end assets → static site build with the content gates → a slim runtime
  with a health check.
- The app gets **its own node in my private network** through a Tailscale sidecar — moved there with a written
  procedure, checked by the independent verifier (GO → PASS). It is not reachable from the internet.
