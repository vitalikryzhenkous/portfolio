## The problem: idle agents are invisible

Several Claude Code sessions run in tmux, one per project. Any of them can stop to ask for permission. A waiting
agent costs nothing — except the hours until someone looks. I wanted that state on a wall-sized glance, not in a
terminal I have to open.

## Hooks write metadata, the board derives state

- **11 hook events** — session start and end, prompt submit, stop, notification, permission request, tool use,
  subagent start and stop, before and after compaction — each append one line to a local log: time, event, a short
  session id, the project, the tool with a file name or the command's first word, the agent's own task titles, and
  whether it waits for a permission or asks me a question.
- **By default never** prompts, responses, file contents or full commands. With an explicit opt-in the hook also
  keeps short, truncated pieces — the start of a command it asks permission for, its question, the end of its last
  reply — and the server gives them only to the token-protected API, never to the LAN tablet.
- The hook prints nothing and always exits 0, so it cannot block or change the agent.
- The **FastAPI** server turns the stream into *working / waiting for you / idle* per session, plus how full the
  context window is and roughly how many turns are left, compactions, running subagents and plan limits.

## One reply, and nothing more

From the apps I can answer an agent that has finished its turn and waits for me. The server types it into that
session's tmux pane only if every rule holds:

- the session runs on this machine inside tmux, and the pane really runs Claude Code;
- the agent waits after its turn — **never** into a permission or question dialog, where a “1” would pick an option;
- one line, at most 500 characters, no control characters, nothing starting with `/`, `!` or `#` — the only command
  allowed is a fixed `/compact`;
- one send per session every few seconds; the log keeps that a reply was sent and how it went, never its text.

Permissions themselves are still answered in the terminal. An earlier button that started a new agent from the tablet
was removed: replying to a running session covers the need with a smaller surface.

## Notion is the source of truth

- Every 5 minutes the board takes a snapshot of the project list from Notion. Projects marked sensitive are
  scrubbed to ID and status before anything is displayed.
- In the evening the board writes one session-log entry per project from the day's hook events and commit subjects.

## Built for an old tablet, extended without code

The display is an iPad mini 2 on iOS 12: ES5-only JavaScript, polling every 10 seconds, separate morning, day,
evening and night screens, and a no-cache policy so Safari never shows a stale board. The tablet cannot join the
private network, so it is the one documented LAN exception: an automated exposure check flagged the board
listening on all interfaces, and the firewall was narrowed from the whole subnet to this one device.

The apps reach a versioned API over the private network with HTTPS and a bearer token. Every server text comes as a
key plus variables, so languages, colour themes (checked for WCAG AA contrast) and the board's cat persona are data
files a user adds outside the repository, validated by a check script.

## What I'd do next

- Per-project time-in-waiting as a metric, to see which tasks need better permissions up front.
- A public, scrubbed demo mode with recorded events, so the board can be shown without the private network.
