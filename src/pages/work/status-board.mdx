## The problem: idle agents are invisible

Several Claude Code sessions run in tmux, one per project. Any of them can stop to ask for permission. A waiting
agent costs nothing — except the hours until someone looks. I wanted that state on a wall-sized glance, not in a
terminal I have to open.

## Hooks write metadata, the board derives state

- **6 hook events** — session start and end, prompt submit, stop, notification, tool use — each append one line
  to a local log: time, event, a short session id, the project, the tool with a file name or the command's first
  word, the agent's own task titles, and whether a notification asks for permission.
- **Never** prompts, responses, file contents or full commands. The hook prints nothing and always exits 0, so it
  cannot block or change the agent.
- The **FastAPI** board turns the stream into *working / waiting for you / idle* per session, next to the project
  list, today's focus and the machine's load.

## Notion is the source of truth; the tablet only points

- Every 5 minutes the board takes a snapshot of the project list from Notion. Projects marked sensitive are
  scrubbed to ID and status before anything is displayed.
- **Start an agent from the tablet:** the tablet sends only an id. The server takes the prompt from the Notion
  snapshot and the folder from the project's repo field, then starts Claude Code in that project's tmux session.
  Nothing typed on the tablet is ever executed; the agent runs in its normal permission mode, so anything risky
  stops at “waiting” — which the board shows.
- At 20:55 the board writes one session-log entry per project from the day's hook events and commit subjects.

## Built for an old tablet

The display is an iPad mini 2 on iOS 12: ES5-only JavaScript, polling every 10 seconds, separate morning, day,
evening and night screens, and a no-cache policy so Safari never shows a stale board. The tablet cannot join the
private network, so it is the one documented LAN exception: an automated exposure check flagged the board
listening on all interfaces, and the firewall was narrowed from the whole subnet to this one device. From the
laptop and phone the board is reached over the private network with HTTPS.

## What I'd do next

- Push notifications for “needs you” instead of polling a screen.
- Per-project time-in-waiting as a metric, to see which tasks need better permissions up front.
